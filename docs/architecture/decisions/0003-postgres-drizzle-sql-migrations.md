# ADR 0003: PostgreSQL + Drizzle with checked-in SQL migrations

Status: Accepted (2026-09-30). Quick reference: D3.

## Context

Data is relational (categories, products, images, sizes, orders, reviews, sessions). Hosting must be swappable (Neon, Supabase, RDS).

## Decision

PostgreSQL 17, Drizzle ORM 0.45 with postgres.js. Migrations are SQL files in `drizzle/` (generated by drizzle-kit plus hand-written CHECK/index SQL), applied by `scripts/migrate.ts` locally and `scripts/migrate.mjs` in the image. Enums are `text` + CHECK constraints generated from `src/domain` vocabularies. Money is integer PKR. Plain Postgres only, no extensions.

## Alternatives considered

- Prisma: heavier runtime/engine, less SQL control (docs/research/stack.md section 9).
- Supabase client/SDK: vendor coupling.
- SQLite/libSQL: simpler locally but weaker fit for managed hosting and concurrent admin writes.
- Postgres enums: harder to migrate than text + CHECK.

## Consequences

- Portable dump/restore, typed queries, SQL-first migrations reviewable in PRs.

* Two migration runners (ts and mjs) must stay in sync.
* Hand-written CHECKs must be mirrored in `src/domain` (tests cover this).
